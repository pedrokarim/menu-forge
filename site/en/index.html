Minecraft inventory studio

Game menus, drawn pixel by pixel.

Menu Forge is a local studio for drawing custom Minecraft inventories—tabs, modals, colored buttons, paginated lists—and opening them in game, on Java and Bedrock alike. Start from one of 22 examples, refine it to the pixel, try the clicks: the studio composes the chest title glyph by glyph, without a single offset computed by hand.

What Menu Forge does

Everything it takes to make a vanilla chest look like a real modded interface, without ever opening a font editor or counting pixels by hand.

Draw

Pixel-exact canvas

Snapped to the slot grid, over a “slots only” or vanilla chest background, with zoom and snapping.

Generated textures

Panels, buttons, slots, tabs and progress bars in three style families—no PNG to draw to get started.

Dynamic texts

Variables ({viewer.name}, {page.number}…) aligned left, center or right, measured with the game's own advances.

Pixel font

Drawn for Menu Forge: with no vanilla pack plugged in, game texts use the same advances as in game, with no Mojang asset at all.

Pixel editor

Pencil, bucket, shapes, selection, lasso, magic wand, layers, symmetry, zoom up to ×64: your textures, exported as PNG.

Free mode

Callouts, key hints, badges: assets exported as PNG and as a glyph, ready to drop into any text.

Bring the menu to life

Areas and actions

Buttons, paginated lists, inputs, decorations; on click: open, go back, change state, play a sound, run a command.

State and conditions

Tabs, pages, flags: every layer and every slot can depend on the state, with a preview of each case.

No JSON required

Click actions, condition trees, state variables and MiniMessage items: everything is edited in the inspector.

Try mode

Click a slot: its actions run as they would in game, a log follows them, and the document never changes.

Components

A pager or a back button drawn once, included in several menus, and resolved identically by the library.

Live composed title

The studio shows, token by token, what the library will write into the title—with the same algorithm.

Work fast

Editing gestures

Multi-selection, copy and paste, align and distribute, groups, locking; drag a PNG straight from the file explorer.

Keyboard first

A shortcut for every gesture, one-key zoom (Z, +, -, Shift+1), and ? lists them all.

Resizable columns

The side columns of all four editors widen with the mouse or the keyboard, and the studio remembers them.

Nothing overflows

From 1024 × 600 up to the largest screen, texts wrap instead of being cut; a layout checker verifies it on every test run.

One-shortcut export

Ctrl+E writes menus and textures into the plugin's folder; the test ZIP pack is identical, byte for byte, to the library's.

Paper library

The MenuForge plugin handles sessions, pages and actions, generates the pack's fonts and opens up to your server through an API. Born for Enderium, it works with any Paper server.

Interface generator

A complete menu in a few settings, or one of the 22 examples in the gallery: layers, slot areas, actions and state are created for you, then edited like any other menu.

Five types, three families

A shop, a simple grid, a confirmation modal, a paginated list or a tab bar; chest rows, number and layout of the buttons; the Deepslate (beveled), mc-rs (dark, rounded) or “dark with accent” (flat) family, and its accent color. The preview follows every setting, and clicking a tab or an arrow changes its state, just like in game.

A gallery of 22 examples

“Voir les exemples” (See the examples), on the home screen, opens the gallery: filters by type and family, thumbnails rendered live by the generator and never stored as images. One click loads an example, “Personnaliser” (Customize) lets you tweak it, a double click creates the menu.

Ordinary menus

There is nothing special about the created menu: pixel-exact generated textures (background, slots, buttons, lit variants), slot areas wired to their actions (tabs, pages, back, close), texts and state variables. The texture generator can also draw each layer on its own.

AI generation

Optional: describe a texture or an interface in a few words, with eleven providers, online or on your own machine. Generation runs in the background, and its result is constrained before you review it.

Nothing leaves without you

No provider is contacted until you enable it in the settings, and API keys go into the system keychain, never into the settings file. Online services bill every generation; ComfyUI, Automatic1111 and Ollama run on your machine.

A constrained result

A texture is snapped back to the pixel grid and an enforced palette, with its background removed; an interface is validated against the format's schema and the library's rules, and its errors are sent back to the model, five attempts at most. The result opens in the editor, for you to review before saving.

In the background

Closing the dialog does not stop a generation. Animated notifications follow its phase, read live from the backend; an indicator in the rail counts running generations; reopening the dialog shows the steps, a timer and the log of attempts. “Annuler la génération” (Cancel generation) stops it for good.

Java and Bedrock

One studio, both editions of the game. On Java, the visuals ride on the chest title; on Bedrock, on a server form drawn with JSON UI.

Java: the Paper plugin

The MenuForge plugin opens a vanilla chest whose title carries the visuals as font glyphs; it generates the pack's fonts and handles sessions, pages and actions.

Bedrock: the mc-rs server

“Export for Bedrock” writes a resource pack (JSON UI layouts, textures) and a runtime descriptor, runtime.json; the native mc-rs server sends the forms and runs the clicks.

Bedrock forms

A menu type of its own, designed for the Bedrock client: a title, some text and buttons, shown in one of the eight layouts of the server's mcrs_ui pack. Each button has its text, a subtitle, a role (banner, special button), an icon and its click actions; a “sent if” condition hides it depending on the state or the player's flags.

The icon comes from the workspace (imported, drawn in the pixel editor, taken from a library), from a game texture referenced by its path (textures/items/diamond) and never copied, or from a web address. The preview follows the geometry of the pack's layouts, and Try mode runs the actions just as the server does.

Chest menus go to Bedrock too: the exporter generates a JSON UI layout for them, with a grid of buttons aligned on the chest slots.

On mc-rs, /mf list lists the menus, /mf open <id> opens one and /mf reload reloads the export without restarting the server.

How it works

The “modern” menus you see on servers are not mods: they are vanilla chests whose title holds images. Menu Forge takes care of the whole chain.

  1. 1

    Draw

    In the studio, from an example, a template or the generator: layers, texts, slot areas, state and actions, without writing any JSON.

  2. 2

    Export

    Ctrl+E: *.menu.json files and their PNGs—readable, versionable, documented—into the plugin's folder.

  3. 3

    Open in game

    The library generates the pack's fonts and opens the menu in a vanilla chest, with its slots and actions.

Under the hood

The chest texture is replaced by a “slots only” image: the frame disappears, the slot cells stay. Everything else is written into the chest's title, with a font in which every character is an image.

For each visible layer, a negative or positive space moves the cursor to the right x coordinate, then the layer's glyph is drawn at the height set by its ascent. The catch: Minecraft then advances by the image's last opaque column plus two, not by its width. Menu Forge crops every layer and measures that advance from the pixels, in the studio and in the library alike.

ascent = 13 − yputs the top of the image at y

advance = last opaque column + 2not the PNG's width

Slots remain real slots, and the title is drawn beneath the items: a button is a layer plus a slot placed at the same spot, often holding an invisible item.

The studio composes the title and generates the fonts with the same algorithm as the library: a shared fixture checks that both produce the same fonts, byte for byte, and the same titles. What the studio shows is what players will see.

Get started

No published release yet: you build from source. Requirements: Node 24, stable Rust (1.95 or later), WebView2 on Windows (included in Windows 11) and JDK 21 for the library.

Desktop app

The studio in its own window (Tauri 2), with a native folder picker and a Windows installer.

git clone https://github.com/pedrokarim/menu-forge.git
cd menu-forge/studio
npm install
npm run tauri:build

The installer is written to studio/src-tauri/target/release/bundle/nsis/.

Browser mode

The same studio, served locally—handy for development and testing.

cd menu-forge/studio
npm install
npm run dev

Then open http://localhost:5173. The server only listens locally and rejects other origins.

Paper plugin

MenuForge reads the exported menus, generates the pack's fonts and opens the menus in game. Paper 1.20.6 and later, Java 21.

cd menu-forge/lib
./gradlew build

Drop MenuForge-<version>.jar into plugins/, the menus exported by the studio (Ctrl+E) into plugins/MenuForge/workspace/, then merge the generated pack into your server's.
